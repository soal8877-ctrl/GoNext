# PLAN.md  
## План поэтапной реализации GoNext (Дневник туриста)

Документ описывает **порядок действий** при разработке MVP по [PROJECT.md](./PROJECT.md).  
Каждый этап завершается проверкой (`npx tsc --noEmit`, `npx expo lint`) и ручным прогоном на телефоне или эмуляторе.

**Текущее состояние репозитория:** минимальный каркас Expo SDK 58 + Expo Router (`src/app/`) + React Native Paper; демо-экран Home. Бизнес-логики, SQLite и полноценного меню пока нет.

---

## Этап 0. Согласование объёма MVP

**Цель:** зафиксировать границы первой поставки и не тащить в MVP пункты из раздела «Будущее развитие» PROJECT.md.

**Действия:**

1. В MVP входят: главное меню, режимы «Места», «Поездки», «Следующее место», «Выражения», заглушка «Настройки» (без сложной конфигурации, если в PROJECT.md деталей нет).
2. Исключить из MVP: PDF, облачную синхронизацию, совместные поездки, статистику, полный маршрут на одной карте.
3. Уточнить у заказчика (при необходимости) тексты 10 фраз для экрана «Выражения» либо заложить нейтральный набор «для путешественника».

**Результат:** понятный чеклист «входит / не входит» перед началом кодирования схемы БД.

## Этап 1. Каркас приложения и навигация

**Цель:** заменить демо-Home на структуру приложения из PROJECT.md §5.

**Действия:**

1. Спроектировать дерево маршрутов Expo Router в `src/app/`:
   - главный экран (меню GoNext);
   - `places/` — список и `[id]` деталь;
   - `trips/` — список и `[id]` деталь маршрута;
   - `next-place` — «Следующее место»;
   - `phrases` — «Выражения»;
   - `settings` — настройки (минимальный экран).
2. В `_layout.tsx` оставить `PaperProvider`, `SafeAreaProvider`, общий `Stack` (без лишних вложенных навигаторов).
3. Главный экран: `Appbar` с заголовком **GoNext**, вертикальный набор кнопок (`Button` / `List.Item`) по PROJECT.md.
4. Единый стиль: отступы, заголовки экранов, кнопка «Назад» через `Appbar.BackAction` или нативный заголовок Stack — выбрать один подход и придерживаться его.
5. Проверить запуск на Android (Expo Go или dev build) и web только для быстрой отладки UI.

**Результат:** по меню можно перейти на все экраны (пока с заглушками «скоро» или пустыми списками).

---

## Этап 2. Слой данных (SQLite)

**Цель:** офлайн-хранение по PROJECT.md §6.

**Действия:**

1. Подключить SQLite для Expo (актуальный модуль под SDK 58, например `expo-sqlite`), изучить документацию версии SDK перед установкой (`npx expo install …`).
2. Описать схему таблиц:
   - `places` — поля из сущности Place;
   - `trips` — поля Trip;
   - `trip_places` — TripPlace (`placeId`, `order`, `visited`, `visitDate`, `notes` + связь с `trips`);
   - таблица/поля для путей к фото (см. этап 6) или JSON-массив путей, если проще для MVP.
3. Реализовать инициализацию БД при старте приложения (миграция v1, idempotent `CREATE TABLE IF NOT EXISTS`).
4. Вынести доступ к данным в модули вне `src/app/` (например `src/db/`, `src/repositories/`), типы TypeScript для `Place`, `Trip`, `TripPlace`.
5. CRUD для мест и поездок на уровне репозитория; для `Trip.current` — правило «только одна текущая поездка» при установке флага.

**Результат:** из кода можно создавать/читать/обновлять/удалять места и поездки без UI или через временные экраны-отладчики.

## Этап 3. Режим «Места»

**Цель:** PROJECT.md §4.1.

**Действия:**

1. Экран списка: `FlatList` / `FlashList` + `List.Item`, пустое состояние, FAB «Добавить место».
2. Форма создания/редактирования: `name`, `description`, флаги `visitlater`, `liked`, координаты `dd` (две числовые поля или одно поле «широта/долгота» с валидацией).
3. Экран детали: описание, координаты, переключатели `visitlater` / `liked`, блок фото (после этапа 6).
4. Кнопка «На карте»: открытие системной карты / Google Maps по координатам через `Linking.openURL` (шаблон geo / maps intent — проверить на Android и iOS).
5. Удаление места с подтверждением (`Dialog`).

**Результат:** пользователь ведёт справочник мест независимо от поездок.

---

## Этап 4. Режим «Поездки»

**Цель:** PROJECT.md §4.2.

**Действия:**

1. Список поездок: название, даты, индикатор `current`.
2. Создание/редактирование поездки: `title`, `description`, `startDate`, `endDate`, флаг «текущая поездка».
3. Экран детали поездки:
   - упорядоченный список `TripPlace`;
   - добавление места из справочника `places` или создание нового места «на лету»;
   - изменение порядка (для MVP: кнопки «вверх/вниз»; drag-and-drop — по желанию, не блокер).
4. Для каждого пункта маршрута: `visited`, `visitDate`, `notes`, фото посещения (этап 6).
5. Визуальное разделение: невизитированные / посещённые (чипы, иконки Paper).

**Результат:** поездка работает и как план, и как дневник после отметок `visited`.

---

## Этап 5. Режим «Следующее место»

**Цель:** PROJECT.md §4.3.

**Действия:**

1. Выбор активной поездки: `current === true`; если нет — понятное сообщение и ссылка на экран поездок.
2. Алгоритм: первая запись `trip_places` с `visited = false`, сортировка по `order`.
3. Показать данные связанного `Place` (название, описание, координаты).
4. Действия: «На карте», «Навигатор» (те же URL, что в §4.3).
5. Опционально в MVP: кнопка «Отметить посещённым» с эт экрана (ускоряет сценарий в пути).

**Результат:** один экран отвечает на вопрос «куда ехать дальше».

---

## Этап 6. Фотографии (локальное хранилище)

**Цель:** PROJECT.md §6, поля `photos[]`.

**Действия:**

1. Выбрать API: `expo-image-picker` для выбора/съёмки; сохранение файлов в `expo-file-system` (каталог приложения).
2. В БД хранить относительные пути или URI, не бинарные blob (проще бэкап и миграции).
3. Подключить галерею на экране места и на пунктах маршрута поездки (раздельные списки: фото места vs фото визита — по модели PROJECT.md).
4. Обработка отказа в разрешениях камеры/галереи (`Snackbar` / `Dialog`).

**Результат:** фото переживают перезапуск приложения и работают офлайн.

---

## Этап 7. Режим «Выражения»

**Цель:** PROJECT.md §4.4 (без редактирования пользователем).

**Действия:**

1. Константа в `src/constants/` (или JSON): ровно 10 пар `{ en, ru }`.
2. Экран `phrases`: `FlatList`, `List.Item` с двумя строками или `Text` + subtitle.
3. Никакой БД и сети; экран доступен из главного меню.
4. Согласовать финальные формулировки с PRODUCT (список фраз).

**Результат:** шпаргалка открывается одним нажатием, офлайн.

---

## Этап 8. Настройки и полировка UX

**Цель:** закрыть пункт меню «Настройки», подготовить приложение к регулярному использованию.

**Действия:**

1. Минимальный экран: версия приложения, кратко «все данные на устройстве», при необходимости — сброс БД с двойным подтверждением (только dev/MVP по согласованию).
2. Единые пустые состояния, индикаторы загрузки при первом открытии БД.
3. Проверка офлайн: авиарежим на телефоне — списки и «Выражения» работают; карты/навигатор требуют внешних приложений (ожидаемо).
4. Локализация интерфейса: русский UI (тексты кнопок как в PROJECT.md).
5. Прогнать `npx expo-doctor`, исправить предупреждения по зависимостям.

**Результат:** меню полное, поведение предсказуемое, нет «висящих» заглушек без пояснений.

## Этап 9. Тестирование и приёмка MVP

**Цель:** сценарии сквозным прогоном.

**Чеклист сценариев:**

1. Создать 3 места → открыть одно на карте.
2. Создать поездку, добавить 4 места, сменить порядок.
3. Назначить поездку текущей → «Следующее место» показывает первое невизитированное.
4. Отметить посещение, добавить заметку и фото → «Следующее место» переключилось.
5. Открыть «Выражения» — 10 строк, без сети.
6. Перезапуск приложения — данные на месте.

**Действия:** исправить найденные баги; обновить README (как запустить, туннель/ngrok при необходимости).

**Результат:** MVP готов к демонстрации.

## Этап 10. После MVP (не в текущем плане работ)

По PROJECT.md §7 — только после стабилизации MVP:

- экспорт в PDF;
- резервное копирование;
- синхронизация;
- совместные поездки;
- статистика;
- маршрут целиком на карте.

Каждый пункт — отдельный мини-план и, при native-модулях, development build вместо Expo Go.

## Технические напоминания при реализации

- Версии пакетов — только через `npx expo install`.
- Маршруты — только в `src/app/`; бизнес-логика — в `src/components`, `src/hooks`, `src/db`, `src/repositories`.
- UI — React Native Paper; не смешивать с кастомными демо-компонентами старого шаблона.
- Перед завершением каждого этапа: `npx tsc --noEmit` и `npx expo lint`.
